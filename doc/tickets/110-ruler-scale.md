# 110: Ruler scale (document-space graduations + numbered labels)

**What to build:** The deferred "ruler scale" item — the other half of the user's "ruler feel" gap (109 was the readout). Today the ruler draws 100 full-width hairlines (1% apart, 0.15/0.38 ink) inside a centred 12px strip, with no numbers between the `0`/`100` bounds, and nothing moves: it reads as a progress bar with a hatch, not as a graduated scale. Rebuild it on the inspiration's measured mechanism: **the scale *is* the document** — a document-length layer (1% of the page height per minor graduation) that slides 1:1 with the page past the fixed lane, majors every 5% numbered in a right-aligned column. The slider (thumb/readout/keyboard/drag, tickets 102/109) is unchanged.

**Blocked by:** 109 (committed `194e036`).

**Measured reference (getartcraft.com, 1440x900; probe `/tmp/opencode/inspo-ruler3.mjs`, `/tmp/opencode/inspo-ruler4.mjs`):**

- **Lane:** 60px fixed at the right edge (x1380–1440), full viewport height.
- **Scale:** a document-length layer whose top sits at −scrollY (measured `−1.0147 × scrollY`; at scrollY 0 its top is 60). A label for document position *k*% therefore lands at screen y ≈ k%·H − scrollY — the layer scrolls past the window, it is not a fixed percentage grid.
- **Ticks hang from the lane's right edge:** minors 10×1px at 40% ink every 1% of the document (their page H = 5812 → 58.12px apart), majors 20×1px at 80% ink every 5% (290.6px). Ticks touch the viewport edge (x1420–1440 / 1430–1440).
- **Labels:** every 5% (`0, 5, 10 … 100`), 9px mono, 50% ink, right-aligned to one column 24px inboard of the lane's right edge (label right edge x1416 vs majors starting x1420). Visible density at 900px: ~15.5 ticks / ~3.1 numbers.
- **Blue:** a **1px horizontal rule** `inset-inline: 0` (full lane) at the readout's top — rect `[1380, 391, 60, 1]`, `rgb(45, 129, 255)` — i.e. a *position marker*, not a fill. 105's note called the inspiration's blue a "progress line"; measured, it is this rule, so our vertical fill is a mis-transcription being corrected here.

**Ours today (probe `/tmp/opencode/probe-110.mjs`, shot `/tmp/opencode/110-1440-zoom.png`):** track 12×844 centred in the 28px lane; `repeating-linear-gradient` at 1%/10% of the *track* (so 100 static hairlines, ~8px apart, independent of the page); blue 1px **vertical** fill from the track's top to the thumb; bounds `0`/`100` centred in the lane; thumb 28px wide (1px past the lane's content box, i.e. 1px past the viewport edge).

**Design (our lane is 32px, not 60px — everything scales to it):**

- **Scale layer:** `.ruler__scale` inside the (now `overflow: hidden`) track: `block-size: var(--page-height)`, `transform: translateY(var(--scale-offset))`. The driver publishes `pageHeight` (scrollHeight) and `scrollY` in the existing `frame()` payload; the ruler view writes them on `[data-ruler]` — as **complete px lengths**, the `--eyebrow-top` pattern (the token gate forbids px in CSS, and a `calc()` negation would need a `px` literal), written only when they change: `--page-height` once per resize, `--scale-offset` as the *already-negated* rounded scroll position (`null` sentinel). CSS still owns all geometry. Rounding is a declared deviation: the slide is 1:1 to within 0.5px, and whole pixels keep sub-pixel churn from re-invalidating style every frame — the same value feeds the marker and the covered-grade test, so the whole ruler stays internally consistent.
- **Graduations:** two gradient layers on the scale with `1%` / `5%` periods — percentages of the layer, i.e. of the document, so no new unit math. Lengths come from existing space tokens: minors `--space-2xs` (4px), majors `--space-xs` (8px) — the inspiration's exact 2:1 ratio, and 13%/25% of our 32px lane against their 17%/33% of 60px. Confined to the right edge with `background-size`/`no-repeat`/`position: right top`.
- **Colours — the 105/108 ramp, no new tokens** (order matches the inspiration's 0.4 < 0.5 < 0.8): minors `--color-border-strong` (0.38 ink, 3.5:1 non-text), labels `--color-text-subtle` (0.55 ink, 5.6:1), majors `--color-text-bright` (0.70 ink, 8.4:1).
- **Labels:** 21 chrome rows (`0 … 100` step 5) built in `ruler.js` like the drums — numbers are chrome (the `0`/`100` bounds already are), no copy, no new keys. `--font-size-2xs`, mono, right-aligned to one column `calc(--space-xs + --border-width)` inboard, `inset-block-start: calc(var(--i) * 5%)` (percentage of the scale = document space) and `translateY(-50%)` so each number is centred on its graduation, as the inspiration's are.
- **`--lane-ruler` 1.75rem → 2rem (28 → 32px):** the label column needs the widest label (`100` = 17.8px at 9.6px mono) + the 8px major + a 1px gap inside the lane's content box — 0.2px of slack at 28px (a fallback-mono advance away from clipping), 4.2px at 32px. Side effects, both benign and logged: the content column is capped by `--container` at ≥1432px wide viewports (so nothing moves there) and is 4px narrower below; and the thumb, now equal to the lane's content box, no longer overhangs the viewport edge by 1px (a pre-existing defect the redesign removes as a side effect).
- **Bounds `0`/`100` stay** (they mark the slider's range) and right-align to the same number column so all the ruler's numbers share one edge. At the extremes nothing is duplicated on screen: at scroll 0 the scale's own `0` sits in the handle's band and is covered (next bullet), and at max scroll the scale's own `100` lands one bound-height *below* the track's bottom edge, so it never enters the window — measured, the last visible grade is `95` at both 1440 and 375, so the bounds pinned at the window's ends are what carry `0` and `100`.
- **Marker:** the vertical blue fill is replaced by the measured 1px horizontal `--color-focus` rule spanning the lane's content box at the thumb's top (the same box the handle occupies; the lane's own 1px left hairline stays continuous, as it is not the handle), drawn after the thumb, so it reads as the handle's position line. `data-ruler-progress` → `data-ruler-marker`.
- **Covered grade:** the handle is opaque, so a grade it sits on can only ever show cut in half — the visual pass caught exactly that (a sliver under the handle at 39.9% depth). The grade whose centre lies in the handle's band is therefore hidden (`is-covered` → `visibility: hidden`) rather than slivered: at 5% spacing against a 48px handle it is never more than one row, and the handle's readout already carries the value — the substitution the inspiration's readout makes for the label it sits on. Both sides of the test are document positions, so it needs no measurement.
- **Known deviation, logged:** the thumb travels `track − thumbHeight`, so the graduation matching the current depth drifts by up to the thumb's height (48px) *below* the thumb's top over the full range, against a 249px label spacing at 1440 (~19%, theirs ~19% of 290px) — the identical construction as the inspiration's (whose readout likewise lags its own scale by its height). The current depth's number therefore emerges just under the handle; the handle's own readout carries the value.
- **Reduced motion:** unchanged — the slide is position tracking (as the thumb's `top` already is), not a transition, so the kill-switch keeps doing exactly what it does today.

**Not in scope:** lane geometry / viewport centering (the deferred companion item — the lanes still reserve layout width here, only the ruler's own width token changes); the thumb's drag surface and touch behaviour (102/103); the readout (109, untouched).
