# 114: Fixed name layer — per-section jump anchors, three states

**What to build:** ticket 3 of the approved roadmap. The rail retired at 112 removed the only fixed section list; 114 reinstates it in the inspiration's form: a fixed full-viewport overlay (measured: `pointer-events-none fixed inset-0 z-40`, under the ruler's z) carrying one **named anchor row per section**, right-aligned near the ruler lane, with **three states** as the page scrolls — **passed** rows pinned at the top, the **current** section's name at ~2× the letter size directly below them, and **upcoming** rows stacked from the bottom. Every row is a real `<a href="#section">` so the jump affordance and keyboard reachability ride the existing global anchor seam (`smooth-scroll.js` handles all `#` links); the copy is the nav's own keys (`nav.hero/projects/skills/education/contact` — no new copy, hero included since our nav names every section; their hero is unnamed and renders as an empty slot).

**Blocked by:** 113 (done, committed `dc975b3`).

**Decisions taken:**

- **New module `src/names/name.js` + `name.css`**, markup inlined in index.html like nav/ruler (the 001 convention). One anchor `<a href="#…">` per section; JS splits the dict-bound name into per-letter `<span>`s (**chrome**, like the hero's split — letter travel's substrate for 115) and marks them `aria-hidden`; the anchor keeps its accessible name via `data-i18n-attr="aria-label=nav.<id>"` so the letter split never breaks the spoken name.
- **Geometry = CSS math over JS ordinals** (the `--ruler-drum-index` pattern): JS publishes only state classes + two unitless counters per flip — `--name-slot` (a row's index within its stack, 0-based) and `--name-passed` on the layer; CSS computes every px with tokens. No document-position measurement in JS; `100vh` in the upcoming calc is theirs' own inset-0 spelling.
- **Positions (all tokens):** `--name-inset: 3.5rem` (56), `--name-stack-top: 4rem` (64), `--name-pitch: 1.25rem` (20), row box `1.5rem` (24, overlap 4px between neighbouring anchors at 20px pitch — theirs is exactly the same overlap), `--name-word-gap: 1.0625rem` (17, the current word's air below the last passed row), `--name-stack-bottom: 1.5rem` (24).
  - Small letter size: `--font-size-base` (1rem), current word: `--font-size-lg` (32px @1440 — the 2× of theirs, right at our 34px measure).
- **The letter line-height puzzle:** their letter line-box (16/34px) vs font-size cannot be reconciled from exported rects alone (their letters, likely SVG-shimmed, measured 34px font in 16px boxes); ours ships the same *visual* consequence with `line-height: 1em` and the measured box heights — the settled form matches the screenshots, which is the contract.
- **z-order: below the ruler, above the content — with the nav above the fixed chrome** (review amendment — measured on the inspiration today: their sticky header is **z50 over their z40 lane**, so corner controls keep their hit targets while the lane owns the empty band; their names layer is one step under their ruler, 39 vs 39/40): `--z-names: 150`, ruler 160, and `--z-nav` raised **100 → 180** because the switch's centre sat 1.5px inside the lane's track since 113 and its clicks died there (found by 114's QA hit-testing the corner control; previously invisible because every earlier harness clicked through JS dispatch).
- **Retires nothing** — the nav's mono links stay as they are (two rungs to the same jump affordance, like theirs: header links + layer rows). Layer hidden `≤768` via `--names-display` in the narrow query (theirs unmounts ≤640; ours rides the v2 narrow boundary like every other switch).
- **Reduced motion:** 114 has no animation of its own — states flip instantly (no transition anywhere on the layer); 115's travel will be the piece gated off under `prefers-reduced-motion`.
